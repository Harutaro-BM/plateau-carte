# PLATEAUカルテ

**3D都市モデル（Project PLATEAU）の建物属性が、自治体ごとに実際どれだけ入っているかを、306自治体すべてで実測した。**

公式の「属性情報公開リスト」は、仕様上その属性があるかの○×で、56都市・2021年更新が最後になっている。
実測すると両方向に食い違う。**公式で○の白河市は建築年が17.5%、公式で空欄の宗像市は78.5%**入っている。

カルテは、データを落として開く前に「この自治体でその分析を始められるか」に答える。

- ビューア：https://harutaro-bm.github.io/plateau-carte/
- ソースコード：https://github.com/Harutaro-BM/plateau-carte

![関東の建築年の充填率。東京都は全域が0%、隣の埼玉県は多くの自治体で入っている](web/map-kanto.svg)

## 全国の結果（2026-09-15 実測）

306/306自治体、標本 10,714,532棟、転送 15.8GB、約43分。

| 属性 | ◎＋○の自治体 |
|---|---:|
| 高さ種別 | 100.0% |
| 高さ | 99.0% |
| 測量年 | 87.3% |
| 用途 | 70.9% |
| 階数 | 58.5% |
| 構造種別 | 55.2% |
| 耐火構造 | 50.3% |
| **建築年** | **15.4%** |

始められる分析（必要な属性がそろっている自治体数）：
時系列比較 267／高さ解析 213／人口推定 174／**耐震・被害推定 86**。
4つすべて可能は44自治体、どれも不可は20自治体。

- **構造種別と耐火構造は、全306自治体で◎か×のどちらかしかない**（中間の段階が0件）。
  整備の仕様で「入れる／入れない」が決まっているということで、自治体を1つ見て全国を推し量ることはできない
- **建築年は県単位でまとまる。**東京都62自治体はすべて0%、隣の埼玉県は49自治体中35で入っている。
  90%以上入っているのは磐田市・焼津市の2市だけ（いずれも静岡県）

「始められる」は必要条件を満たすという意味で、分析結果の精度は保証しない。

## 開くまで中身が分からない理由

1. **充填率がどこにも公開されていない。**公式の属性一覧は仕様上の○×で、56都市・2021年の更新が最後。データセットの説明にも充填率は無い
2. **zip は自治体の全データの束になっている。**建物の属性を確かめるだけでも、地形や道路ごと落とすことになる
3. **値が入っていても情報が無い場合がある。**`usage=461`（不明）などのダミー値が、値として入っている（下の「測り方」を参照）

全306自治体の最新年度の zip を、目次だけ読んで測った（2026-09-29、`scripts/zip_sizes.py`）。

| | 値 |
|---|---|
| zip の大きさ | 中央値 0.48GB、90%点 7.3GB、最大 269GB（浜松市） |
| 全306自治体の合計 | **1,463GB。うち建物は 55GB（3.8%）**。大半の 1,336GB は地形（DEM） |
| zip に占める建物の割合 | 中央値 14.7%。浜松市は 269GB のうち 0.23GB（0.1%） |

カルテは zip の目次だけを読み、建物の部分だけを取り寄せる。全国の走査で転送したのは 15.8GB。

## 始められる分析の判定

必要な属性の充填率がすべて閾値以上なら「可」とする（`scripts/scan.py` の `derive()`）。

| 分析 | 条件 |
|---|---|
| 人口推定 | 用途60%以上 かつ 階数60%以上 |
| 高さ解析 | 高さ90%以上 かつ 高さ種別60%以上 |
| 耐震・被害推定 | 建築年40%以上 かつ 構造種別60%以上 |
| 時系列比較 | 測量年60%以上 |

- **4つは代表的な使い道の例**で、ほかの分析（浸水被害、太陽光など）は判定していない
- 閾値は作成者が決めたもの。**「可」は必要な属性がそろっているという意味で、結果の精度は保証しない**
- 標本の誤差（最悪2.8ポイント）があるので、閾値の近くでは判定が揺れる（例：東村山市は高さ89.9%で高さ解析「不可」）

## 過去年度との比較（2026-09-29 実測）

2年度以上のデータがある133自治体のうち106件で、最古年度と最新年度を比べた。
**両年度に共通するメッシュだけ**を、同じ層化抽出で選び、同じメッシュを両年度で読んでいる。

- **106件中73件で、少なくとも1つの属性の段階が上がった**（下がったのは10件）。
  仕様の世代が同じ更新（v4→v5）でも51件中37件が上がり、下がったのは0件
- ただし**建築年の段階が変わったのは106件中8件だけ**。東京都は53件すべてが両年度とも0%
- **更新で属性が丸ごと消えた自治体がある。**元のファイルで要素そのものが無いことを確かめた

| 自治体 | 年度 | 属性 | 旧 → 新 |
|---|---|---|---|
| さぬき市 | 2023→2024 | 建築年 | 59.0% → 0% |
| 東村山市 | 2020→2025 | 構造種別 | 84.9% → 0% |
| 益城町 | 2020→2023 | 建築年 | 45.6% → 0% |

比較できなかった27件のうち25件（静岡県23件）は、古い年度が 7z 形式で配布されていて、zip のように目次だけを読めない。
25件で合計437GBあるため外した。**建築年についての結論は、静岡県をほぼ含まない。**
詳細は [docs/06-vintage-compare.md](docs/06-vintage-compare.md)。

## 測り方

- 各自治体の最新年度の CityGML（建物）を対象にする。zip の中央ディレクトリを HTTP レンジ要求で読み、必要なメッシュだけを取得する
- **標本は層化抽出。**メッシュを非圧縮サイズ順に並べて総バイト数で4層に等分し、各層から6メッシュ（最大24）を等間隔に選ぶ。
  乱数を使わないので、誰が走らせても同じメッシュが選ばれる
- 全数が分かっている12自治体（階数）で、標本の誤差は**平均0.6pt・最悪2.8pt**。
  以前の方式（サイズの大きい3メッシュ）は密集市街地に偏り、平均9.8pt・最悪66.7pt だった
- 値として入っているダミーを除外する：`measuredHeight=-9999`、`storeysAboveGround=9999`、`usage=461`（不明）、`surveyYear=0001`、建築年の1800以下・2100以上
- 出力は段階評価（◎90%以上／○60〜90%／△20〜60%／▲0〜20%／×0%）。
  最悪2.8ptの誤差があるので、小数で自治体の順位は付けない

詳細は [docs/00-spec.md](docs/00-spec.md)（仕様）と [docs/04-stratified-sampling.md](docs/04-stratified-sampling.md)（標本設計と検証）。

## 再現手順

```bash
python scripts/names.py       # 自治体コード → 日本語名（306件）
python scripts/scan.py        # 全国走査（約43分・転送約16GB）。途中保存があるので、中断しても再実行で続きから
python scripts/rebuild.py     # 地図の生成と web/ への配布
python -m http.server 3200 --directory web

python scripts/compare_vintages.py   # 過去年度との比較（133自治体・4並列で約2時間）。途中保存あり
python scripts/analyze_vintages.py   # 比較の集計
```

- 走査とビューアは Python 3.12 の標準ライブラリだけで動く。ビューアは依存ライブラリなしの静的HTML
- 地図の生成（`build_map.py`）だけ DuckDB の空間拡張を使う（`pip install duckdb pandas`）。
  都道府県ごとの行政区域データを `data/n03/` に落とす（数百MB）
- 走査対象の一覧は `data/plateau_coverage.json`（走査時点の306自治体）を同梱している。
  `python scripts/fetch_coverage.py` で取り直すと、その後に追加された自治体も入るので結果は変わる

## 更新への追従

`.github/workflows/refresh.yml` が毎月、PLATEAU の更新を検知する（`scripts/check_updates.py`）。
新しい自治体・新しい年度・走査後に差し替えられたデータセットを見つけ、`scripts/refresh.py` が該当する自治体だけを走査し直す。

**2027-02-27（PLATEAU AWARD 2026 の最終審査）までは、走査し直さないよう止めてある。**
`config/auto_update.json` の `enabled` が `false` で、さらに `notBefore` が `2027-02-28` になっている。
両方を満たさない限り、検知の結果を Actions の記録に出すだけでリポジトリは変えない。
走査し直した後は、README とビューアの説明文に書いた数値を人が読み直すこと（説明文は自動では直らない）。

## 主なファイル

| パス | 内容 |
|---|---|
| `data/carte.json` | 自治体ごとの充填率・段階・始められる分析 |
| `data/carte_top3_2026-08-19.json` | 以前の方式（上位3メッシュ）の結果。比較用 |
| `data/grade_diff.json` | 以前の方式との段階の差（2,448判定中、下方142・上方23） |
| `data/vintage_compare.json` | 過去年度との比較（自治体ごとの両年度の充填率・段階） |
| `data/vintage_summary.json` | その集計 |
| `data/zip_sizes.json` | 各自治体の zip の大きさと、そのうち建物が占める量 |
| `config/auto_update.json` | 自動の再走査を止めておくフラグ |
| `web/` | ビューア（`index.html`・`carte.json`・`names.json`・地図SVG） |
| `scripts/scan.py` | 全国走査 |
