# PLATEAUカルテ 仕様

> **この文書は 2026-08-19 時点の仕様。**その後、標本の取り方を「サイズの大きい3メッシュ」から層化抽出（最大24メッシュ）に変え、2026-09-15 に全306自治体を再走査した（経緯と検証は [04-stratified-sampling.md](04-stratified-sampling.md)）。**最新の数値は [README](../README.md) とビューアを参照。**

作成 2026-08-19 / 状態 **全国走査完走。ビューア動作確認済み**

## 何を作るか

**3D都市モデルの属性が、自治体ごとに実際どれだけ入っているかを測って公開する。**

公式が公表しているのは「各整備都市に含まれる地物のLODと属性情報の**一覧**」で、
これは**仕様上その属性があるか**の○×である。実測すると同じ○の中に
**建築年73.8%の自治体と0%の自治体**が混在している。

| 自治体 | 公式の属性一覧 | 実測 |
|---|---|---|
| 伊東市 | 建築年 ○ | **92.6%** |
| 三島市 | 建築年 ○ | **89.1%** |
| 湖西市 | 建築年 ○ | **80.5%** |
| 静岡市 | 建築年 ○ | **73.2%** |
| **掛川市** | 建築年 ○ | **0%** |
| 河内長野市 | 用途 ○ | **19.8%**（461「不明」が80.2%） |

（初期の測定では自治体コードの転記誤りとサンプリングの欠陥があり、
「富士宮市73.8%」「静岡市46.1%」と記録していた。実際は三島市89.1%・静岡市73.2%。
経緯は [01-flagship-result.md](01-flagship-result.md) に残した）

**○と×では表せない。**ここを埋める。

## なぜこれが要るのか

このworkspaceで9案を検討し、6案が死んだ。死因のうち複数が
**「データを開いて初めて分かった」**型だった。

| 死んだ案 | 開いて分かったこと |
|---|---|
| 資材ストック・断熱世代など | 東京23区・大阪府では建築年が全件null |
| 建物単位人口の全国展開 | 用途判明率が19.8〜94.1%で、誤差が6.4〜41.0%に開く |
| 年度間変化検出 | IDが継承されるかが自治体・年度依存 |

**開く前に分かれば、企画の生死が数分で判定できる。**
開発者にとっては数日のパースを省け、国交省にとっては整備優先度の材料になる。

## 測る項目

| 項目 | CityGMLの要素 | 除外するダミー値 |
|---|---|---|
| 高さ | `bldg:measuredHeight` | **−9999** |
| 用途 | `bldg:usage` | **461**（不明） |
| 階数 | `bldg:storeysAboveGround` | **9999** |
| 建築年 | `bldg:yearOfConstruction` | 1800年以下・2100年以上 |
| 構造種別 | `uro:buildingStructureType` | — |
| 耐火構造 | `uro:fireproofStructureType` | — |
| 測量年 | `uro:surveyYear` | **0001** |
| 高さ種別 | `uro:lod1HeightType` | — |

**ダミー値が値として入っているのが最大の罠である。**`NULL`ではないので、
気づかずに平均を取ると壊れる。カルテはこれを除いて数える。

## 出力：段階評価にする理由

| 段階 | 充填率 |
|---|---|
| ◎ | 90%以上 |
| ○ | 60〜90% |
| △ | 20〜60% |
| ▲ | 0〜20% |
| × | 0%（入っていない） |

**小数点1桁を出さない。**
全市を読んだ5都市で市域を10帯に分け、帯ごとの充填率のばらつきを測った結果がこれ。

| 自治体 | 全市 | 帯別の範囲 | 幅 |
|---|---:|---|---:|
| 熊谷市（n=130,725） | 94.1% | 93.2〜94.9% | 1.6pt |
| 台東区（n=65,778） | 93.8% | 92.0〜95.5% | 3.5pt |
| 荒川区（n=83,500） | 93.9% | 90.6〜95.5% | 4.9pt |
| 中央区（n=35,216） | 91.3% | 84.7〜94.7% | 10.0pt |
| 河内長野市（n=50,280） | 19.8% | 11.5〜29.1% | 17.6pt |

**「94% 対 19.8%」の桁の差を判定するには十分だが、
「94.1% 対 91.3%」の順位付けには足りない。**
だから段階で出す。小数を出すのは過剰精度で、サンプリング誤差に埋もれる。

## 標本の取り方

**1自治体あたり、建物数の多い3メッシュを読む。**

- 全メッシュを読むと1自治体で数十〜数百MB、306自治体で数十GBになり非現実的
- 実測（完走後）：**1自治体あたり約15MB・約15秒、306自治体で4.7GB・75分**

**メッシュの選び方に落とし穴がある。**
コード順の先頭3件を取ると市域の縁を引いて建物0件になる
（台東区で実際に起きた。河内長野市n=6、札幌市n=9、福岡市n=4も同じ原因）。
**非圧縮サイズの大きいメッシュを選ぶ**ことで回避する。

修正の効果は大きかった。**札幌市の建築年は、縁メッシュでは0%、
建物の多いメッシュでは○（60%以上）**になった。

## 導出：どの分析ができるか

充填率をそのまま出すだけでは「で、何ができるのか」が伝わらない。
検証済みの手法に紐づけて判定する。

| 分析 | 条件 | 根拠 |
|---|---|---|
| **人口推定** | 用途60%以上 かつ 階数60%以上 | 住宅系床面積×階数で国勢調査人口を再現。低層密集市街地で**中央値誤差6.4〜6.7%**（従来の面積按分は33.3%） |
| **高さ解析** | 高さ90%以上 かつ 高さ種別60%以上 | 高さの値だけでは軒高か最高高さか分からない |
| **耐震・被害推定** | 建築年40%以上 かつ 構造種別60%以上 | 新耐震（1981年6月）前後と木造/非木造の判別 |
| **時系列比較** | 測量年60%以上 | 整備年度が違っても測量が同じなら現実の変化を含まない |

## 技術構成

| ファイル | 役割 |
|---|---|
| `scripts/scan.py` | 全国走査。CKANから最新年度のCityGML URLを取り、建物数の多い3メッシュを解析。途中保存あり |
| `scripts/names.py` | 自治体コード→日本語名（CKANのデータセット名から一括抽出、306件） |
| `web/index.html` | 静的ビューア。依存なし。`carte.json` と `names.json` を読む |
| 共用 | `../plateau-timeseries/scripts/` の `remote_zip.py`（レンジ取得）、`parse_bldg.py`（v2〜v5解析） |

**`remote_zip.py` が要点。**PLATEAUのzipは自治体まるごとで200MB〜1.1GBあり、
建物モデルだけ取れない。zipの中央ディレクトリをHTTPレンジ要求で読み、
必要なメンバだけ取る（9.2MBのzipの一覧取得で**転送0.84MB**）。

## 正直に書く限界

| 限界 | 内容 |
|---|---|
| 標本 | 1自治体3メッシュ。市域全体の値ではない。だから段階評価にしている |
| 帯別のばらつき | 1.6〜17.6pt。境界付近（例：60%前後）の段階は揺れる |
| 年度 | 最新年度のみ。過去年度は測っていない |
| 属性の意味 | 「入っている」を測るだけで、値が正しいかは測っていない。**検証を試みたが識別子が噛み合わず不成立**（[02-verify-year.md](02-verify-year.md)） |
| **建物名が無い** | **PLATEAUに建物名が無いため、名称で建物を識別する公的資料との突合ができない。**建物単位の照合を要する検証は、この制約を先に確認すること |
| 学術的先行 | **3D City Index**（Lei & Biljecki 2025、世界47モデル、PLATEAU 27/47）が存在する。ただしあちらは**同じ不整合を「Partially Yes」と記すだけ**で数値化していない |

## 隣接する既存物との違い

| 既存物 | 違い |
|---|---|
| 公式の属性一覧 | **仕様上の有無（○×）。実測充足率ではない** |
| PLATEAU GIS Hub（2025ファイナリスト） | **取得**の道具（ポリゴン選択でDL）。カルテは**品質の診断** |
| 3D City Index（学術） | データセット単位で「Partially Yes」まで。自治体別の数値と下流誤差への影響は無い |

- ✅ 全国走査の完走（306/306、標本240.9万棟）
- ✅ ビューアの動作確認（全データで検証）
- ❌ **目玉項目は2回試して2回失敗**（[01-flagship-result.md](01-flagship-result.md)）
- ❌ **建築年の「正しさ」の検証も不成立**（[02-verify-year.md](02-verify-year.md)）。
  公的リストは建物名で識別するがPLATEAUに名称が無く、ジオコーディングは街区までしか解けない

## 目玉項目についての結論

「属性が欠けると下流の推定が劣化する」ことの実証は**2回試して2回とも失敗した**。
詳細は [01-flagship-result.md](01-flagship-result.md)。

- 1回目：震度を全域一定と仮定 → 支配要因を欠いて順序が逆転
- 2回目：震度メッシュを入れた → n=18では (A)0.699>(B)0.644>(C)0.579 と綺麗に並んだが、
  **n=33に増やすと (B)0.525>(C)0.484>(A)0.474 に崩れた**

**再現しなかったので使わない。**カルテの主張は狭めたまま据え置く。

> **カルテは「始められるか」に答える。「うまくいくか」は保証しない。**
